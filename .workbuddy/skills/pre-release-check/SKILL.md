# 发布前检查 Skill

## 用途

在发布/推送前，自动扫描项目，揪出「不该出现在提交里的东西」。防止把密钥、内部地址、临时部署文件带上公网。

## 何时使用

- `git push` 之前
- 部署云函数 / 静态托管到公网之前
- 怀疑有密钥或内部地址泄露时
- 每个版本发布前的例行体检

## 检查项（按严重程度排序）

### P0 — 致命（命中必须阻断发布）

| 项 | 检查内容 | 为何致命 |
|---|---|---|
| 密钥泄露 | 非 `.env` 文件中出现 `CLOUDBASE_API_KEY`、`service_role`、或 JWT 形如 `eyJ...`（20+ 字符） | 密钥一旦入库，等于把数据库钥匙发到公网 |
| .env 被跟踪 | `.env` 被 `git ls-files` 列出 | `.gitignore` 保护失效，本地秘密会被提交 |
| 临时部署文件 | 存在 `cloudbaserc.deploy.json`（含明文密钥） | Day 17 起部署脚本会临时生成，含密钥，绝不能入库 |

### P1 — 严重（强烈建议修复）

| 项 | 检查内容 | 为何要修 |
|---|---|---|
| 公网网关地址硬编码 | 代码里写死 `api.tcloudbasegateway.com` + `ENV_ID` | 暴露环境 ID 与网关入口，便于被探测 |
| 明文 http 链接 | 出现 `http://`（非 https）的资源引用 | 明文传输，可被劫持篡改 |

### P2 — 提示（可选优化）

| 项 | 检查内容 | 为何提示 |
|---|---|---|
| 调试输出残留 | 代码里 `console.log` 打印敏感对象（key/token/secret） | 生产环境日志泄露风险 |

## 执行方式

本 Skill 配有一个可执行检查器 `check.py`（Python，零第三方依赖）：

```bash
python .workbuddy/skills/pre-release-check/check.py
```

脚本会：
1. 扫描仓库内所有文本文件（跳过 `.git`、`node_modules`、`dist`、`.workbuddy`）
2. 逐条匹配上述检查项的规则
3. 输出逐项结果：`通过 / 未通过`，未通过项附「文件:行号:匹配内容」
4. 最后给出总判定：`✅ 可以发布` 或 `❌ 存在发布隐患，禁止发布`

## 判定标准（完成后逐项确认）

- [ ] P0 项全部通过（无密钥泄露 / .env 未被跟踪 / 无临时部署文件）
- [ ] P1 项无新增（新代码未引入硬编码网关地址或明文 http）
- [ ] 对当前项目实跑一遍，结果可复现
- [ ] 故意埋一个问题，验证 Skill 能查出来（证明不是「永远通过」的虚报）

## 修复指引

- **密钥泄露**：把密钥移入 `.env`，代码里用 `process.env.X` 读取；已泄露的密钥需在平台上**吊销并重新生成**，单纯删除提交不够。
- **.env 被跟踪**：`git rm --cached .env` 并从历史清理；确认 `.gitignore` 含 `.env`。
- **临时部署文件**：删除，并确认 `.gitignore` 含 `cloudbaserc.deploy.json`。
- **公网地址硬编码**：抽到环境变量 / 配置层。
- **明文 http**：升级为 `https://`。

## 卡住降级（最小可用版本）

若时间紧，先只做 P0 中的「公网地址硬编码」+「密钥泄露」两项，其余后续逐步补。
