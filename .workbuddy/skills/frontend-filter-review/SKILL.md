# 前端筛选交互审查 Skill

## 用途

给数据列表（工具列表、卡片列表等）新增或审查「筛选/过滤」功能时，按本规范执行，保证交互完整、无障碍、状态可恢复。

## 何时使用

- 给列表增加按分类/标签/关键词筛选
- 审查已有筛选是否遗漏状态或无障碍问题
- 验证筛选交互的三种关键情况

## 核心规则

### 1. 三种情况必须全部覆盖（硬性标准）

| 情况 | 用户操作 | 期望表现 |
|---|---|---|
| 有结果 | 选中某分类 | 只显示该分类项，结果数正确 |
| 无结果 | 选中无匹配分类 | 显示明确的「无结果」空态（不是空白），并给出可恢复路径 |
| 清空恢复 | 点「全部」或清空筛选 | 恢复完整列表，无残留状态 |

### 2. 筛选控件规范

- 控件须有可感知的「当前选中」状态（如按钮高亮、aria-pressed）
- 「全部」选项必须存在，作为清空筛选的显式入口
- 筛选结果数量有变化时，可用 aria-live 或视觉计数提示

### 3. 可访问性检查（余力项，但推荐）

- 筛选控件可用键盘 Tab 聚焦、回车/空格触发
- 选中状态通过 `aria-pressed` 或 `aria-current` 暴露给读屏
- 颜色不作为唯一区分手段（选中态要同时有形状/边框变化）

### 4. 纯前端约束

- 筛选仅作用于本地数据，不发起网络请求（与项目「零联网」原则一致）

## 执行步骤

1. 读取数据源，列出可用的筛选维度（如 tag 分类）
2. 生成去重后的筛选项 + 「全部」
3. 实现筛选逻辑：点击 → 过滤 → 重渲染
4. 逐条验证「有结果 / 无结果 / 清空恢复」三种情况
5. 用浏览器实测（含键盘操作），确认无控制台报错

## 判定标准（完成后逐项打勾）

- [ ] 有结果情况：筛选后列表正确
- [ ] 无结果情况：显示空态文案且非空白
- [ ] 清空恢复：点「全部」恢复完整列表
- [ ] 控件有明确的选中态
- [ ] 键盘可操作（Tab 聚焦 + Enter 触发）
- [ ] 控制台零报错
